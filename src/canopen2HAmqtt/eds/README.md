# Как создавать EDS-файлы для новых устройств

## Что такое EDS-файл?

EDS (Electronic Data Sheet) — это текстовый файл в формате INI, который описывает "карту" объектов вашего CANopen-устройства. Библиотека `python-canopen` и, соответственно, `canopen2HAmqtt` используют этот файл, чтобы понимать, по каким адресам (индексам) находятся те или иные параметры (имя устройства, его статус, команды для управления и т.д.).

Без EDS-файла `canopen2HAmqtt` не сможет общаться с устройством, кроме как на самом базовом уровне.

## Создание нового EDS-файла

Процесс создания файла для нового устройства состоит из нескольких шагов.

### 1. Используйте шаблон

Лучший способ начать — скопировать существующий шаблон `header.eds.tpl` в новый файл с осмысленным названием, например, `my_new_device.eds`.

Этот шаблон уже содержит все **обязательные стандартные объекты**, которые `canopen2HAmqtt` ожидает найти на устройстве:

*   `[DeviceInfo]`: Общая информация (имя производителя, поддерживаемые скорости).
*   `[1008]` **DeviceName**: Имя устройства, которое можно читать и записывать.
*   `[1017]` **ProducerHeartbeatTime**: Время для мониторинга доступности устройства.
*   `[1018]` **Identity**: **Самый важный объект!** Он содержит:
    *   `VendorId` (ID производителя)
    *   `ProductCode` (ID продукта)
    *   `RevisionNumber` (Версия прошивки)

> **ВАЖНО:** Значения `VendorId` и `ProductCode` в этом файле должны **в точности совпадать** со значениями, зашитыми в прошивку вашего нового устройства. Именно по этой паре `canopen2HAmqtt` находит нужный EDS-файл.

### 2. Добавьте описание сущностей (Entities)

`canopen2HAmqtt` использует специальный подход для обнаружения сущностей (реле, сенсоров и т.д.). Ваша прошивка должна предоставлять их по следующим индексам:

#### а) Список сущностей (индекс `0x2001`)

Прошивка должна отдавать по этому индексу массив типа `UNSIGNED32`. Каждый элемент этого массива описывает одну сущность (например, одно реле или один датчик). `canopen2HAmqtt` читает этот массив, чтобы понять, сколько и каких сущностей есть на устройстве.

Вам не нужно описывать этот объект в EDS-файле вручную, так как `canopen2HAmqtt` знает о нем и добавляет его в словарь объектов автоматически во время работы.

#### б) Конфигурация каждой сущности (индекс `0x2000 + 16 * N`)

Для каждой сущности `N` из списка выше, ее метаданные (например, имя по умолчанию, класс устройства) должны находиться по адресу `0x2000 + 16 * N`.

Например:
*   Для первой сущности (N=1): индекс `0x2010`.
*   Для второй сущности (N=2): индекс `0x2020`.
*   ...и так далее.

Вам нужно описать эти объекты в вашем новом EDS-файле, если вы хотите задать для них какие-то значения по умолчанию. Например, чтобы определить имя по умолчанию для первой сущности, вы можете добавить в `.eds` файл:

```ini
[2010]
ParameterName=Entity 1 Metadata

[2010sub1]
ParameterName=Name
ObjectType=7
DataType=9 ; VISIBLE_STRING
AccessType=RW
DefaultValue=Default Relay Name
```

В большинстве случаев, вам **не нужно** добавлять эти объекты в EDS, так как `canopen2HAmqtt` также обрабатывает их динамически. EDS-файл в основном нужен для `Identity` и других стандартных объектов.

### 3. Интеграция с `canopen2HAmqtt`

Последний шаг — "познакомить" `canopen2HAmqtt` с вашим новым устройством и его EDS-файлом.

Откройте `config.yaml` вашего аддона и добавьте новую запись в список `devices`:

```yaml
devices:
  - vendor_id: 0x00000BEE
    product_code: 0x0000F103
    eds_file: "bluepill.eds"
    model_name: "blue-pill-relay-can"
  
  # Ваше новое устройство
  - vendor_id: 0xВАШ_VENDOR_ID  # ID из прошивки и EDS-файла
    product_code: 0xВАШ_PRODUCT_CODE # ID из прошивки и EDS-файла
    eds_file: "my_new_device.eds"     # Имя вашего нового EDS-файла
    model_name: "My Awesome New Device" # Имя модели для Home Assistant
```

После перезапуска `canopen2HAmqtt` будет готов работать с вашим новым устройством.
